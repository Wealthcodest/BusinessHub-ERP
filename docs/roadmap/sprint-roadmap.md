# Sprint Roadmap

Each two-week sprint has a single measurable outcome, a groomed backlog, acceptance criteria, and a demo. Plan at roughly 80% of observed capacity to leave room for defects and review.

Near-term sequence: stabilize Business module behaviour and UI conventions; deliver Customers; establish Laravel authentication and Business API; migrate Business persistence; then deliver Inventory discovery and core catalog. In every sprint, reserve time for automated checks, accessibility review, documentation updates, and debt reduction.

Stories are done only when code is reviewed, relevant checks pass, acceptance criteria are demonstrated, and user-facing changes are documented.
